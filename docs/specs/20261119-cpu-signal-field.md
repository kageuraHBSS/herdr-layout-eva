# シグナルフィールドの CPU 使用率連動

- 日付: 2026-11-19
- 状態: 承認済み（2026-11-19）
- 対象: `mods/eva-chrome/signal.js`（新規）、`mods/eva-chrome/command.js`（`signal()` と `commandDeck()`）、`mods/eva-chrome/main.js`、README.md、RECIPE.md、tests/

## 目的

コマンドデッキ上部のシグナルフィールドで、CPU 使用率が読めるようにする。負荷が低いときは横の動き（往復距離）が小さく、オレンジ層と紫層が重なって静かにしている。負荷が高いほど大きく往復し、2層は位相も位置もずれて重ならなくなる。波の縦の高さは変えない。

現状のフィールドは `SCHEMATIC`（計測値を表さない装飾）で、HOST の数値には反応しない（RECIPE.md:16-17）。本変更でこの方針を改める。

## やらないこと

- CPU 以外（メモリ・ネットワーク・温度・電源）との連動。
- 線の形（位相）をなめらかに補間すること。ネイティブ補間がないため、値は段階が変わったときに切り替わる。
- 波の縦の高さ（振れ幅、高さの 0.48 倍）の変更。全段階で現在の値に固定する。
- 今の動きを超える往復距離。最上段（段階9）が現在の見た目になる。
- 周期の変更。オレンジ 42 秒、紫 57 秒のまま。
- 目盛り・十字マーク・`−4 … +4` 軸ラベル・左上の `SIGNAL FIELD / PHASE REFERENCE` の変更。

## 段階（level）

CPU 使用率 `machine().cpu`（0〜100、5 秒ごとに更新、最初の読み取りまでは `null`）を、10% 刻みの 10 段階（0〜9）に丸める。

- 素の段階は `min(9, floor(cpu / 10))`。100% は段階 9 に入る。
- ヒステリシスを入れる。上がるときは境界を超えたら即座に上げ、下がるときは境界を 3pt 下回ってから下げる。
  - 素の段階が前回以上なら、素の段階を採る。
  - そうでなければ `min(9, floor((cpu + 3) / 10))` と前回のうち小さい方を採る。
  - 例: 前回 2 のとき、cpu 18 なら 2 のまま。16.9 なら 1。5 なら 0。
- `cpu == null` のときは前回の段階を保つ。前回もなければ 0。
- 段階を決める入力は瞬時値ではなく、直近 6 回（30 秒）の取得値の平均とする。段階の変更は最短でも 30 秒に 1 回（DWELL）とし、最初の取得値では即座に決める。
  - 理由（実装後の実測で判明し、ユーザーと合意）: `ps` 合計値は 5 秒ごとに ±10pt ほど揺れる。瞬時値のままだと、無負荷・中負荷・全コア負荷のいずれでも 11 回の遷移中 6〜7 回段階が変わり、loop が約 10 秒ごとにやり直されて往復が見えなかった。同じ取得値を平均と DWELL に通すと、変化は 0〜1 回になった。
  - 純粋関数 `nextLoad(load, cpu, now)`（`signal.js`）が `{ samples, mean, level, changedAt }` を返す。view の `load` に持ち、`machine()` の戻り値（取得ごとに新しいオブジェクトになる）が変わったときだけ 1 回進める。描画は取得より頻繁に起きるため。
- 純粋関数 `cpuLevel(cpu, previous)` として `signal.js` から export する（`command.js` は `gpui-base` などテストでスタブのない実行時モジュールを import するので、`machine.js` と同じく純粋な部分を別ファイルに分ける）。状態は view（`WorkspaceChrome` インスタンス）に持つ。module レベルには置かない（同じ mod ファイルのコピー間で共有されるため）。

## 段階 → 見た目

`k = level / 9` として線形に対応させる。純粋関数 `signalShape(level)` として `signal.js` から export する。

| パラメータ | 段階0 | 段階9（= 現在の値） |
|---|---|---|
| 紫層の位相（オレンジは常に 0） | 0 | 1.8 |
| 往復距離 `travel`（フィールド幅に対する倍率） | 0 | 0.6 |

- オレンジ層は `-PAD·w → -(PAD + travel)·w`、紫層は `-(PAD + travel)·w → -PAD·w` を往復する（向きは現状どおり）。
- 段階 0 では `travel = 0` なので loop を付けない。2層とも `left = -PAD·w`、位相 0 になり、完全に重なって静止する。
- 層の長さ `SPAN` は最大の往復距離 0.6 に合わせて固定する（`1 + 0.6 + 2·PAD` = 2.6 幅）。どの段階でも線の端は見えない。点数（1 本あたり 121 点）も変えない。
- loop の `id` は `signal-wave-${index}-${幅}-${level}` とする。リサイズしたときと段階が変わったときだけ、新しい範囲で loop をやり直す。やり直すと波は開始位置に戻る。これは仕様として受け入れる。

## 停止と表示

- HOLD（クリック、`shared("eva.signal")`）と MOTION OFF では、今まで通り loop を付けない。各層は loop の開始位置（オレンジ `-PAD·w`、紫 `-(PAD + travel)·w`）で静止する。位相は、その時点の段階を反映し続ける。
- 右上ラベルの `SCHEMATIC` は `CPU LOAD n%` に置き換える（n は 30 秒平均 `Math.round(mean)`、取得前は `--`）。HOLD 中は `CPU LOAD n% / HOLD`。
- 表示条件（デッキ幅 560px 以上）とサイズの追従は変えない。HOST パネルが隠れる 1400px 未満でも、CPU は取得し続けている（`startMachine` は command deck で常に動く）ので連動する。

## エラー時の振る舞い

- 取得に失敗した回は前回の読み取りが残る（machine.js の既存の振る舞い）。そのため段階も保たれる。
- 一度も取得できていない間は段階 0、ラベルは `CPU LOAD --%`。

## 検証

- vitest（`tests/signal.test.js`）:
  - `cpuLevel`: 境界（0, 9.9, 10, 99, 100）、上昇は即時、下降は 3pt 下回ってから、`null` で保持・初期 0、冪等性。
  - `signalShape`: 段階 0 と 9 の値、途中の段階で単調に増えること。
  - `nextLoad`: 最初の取得値で即座に決まる、`null` で変わらない、直近 6 回の平均、DWELL 未満では変わらない、実測した揺れる取得値で段階が変わらない。
- `bun run test`（`vitest run`）の全体が通ること。
- 実機確認: 無負荷で 2 層が重なって静止する。`yes > /dev/null` を複数本走らせて負荷を上げると、横の往復と 2 層のずれが段階的に大きくなる。止めると段階が下がる。HOLD・MOTION OFF で静止し、ラベルが期待どおりになる。
